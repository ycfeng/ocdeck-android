## Highlights / 亮点

- Use the retained client-side `/fork` command to search the loaded, eligible user messages on the active branch, or start from an eligible user-message action. Confirming a selection asks the server to create a new root session and restores the selected prompt into the new Composer. / 使用保留的客户端 `/fork` 命令搜索当前活动分支中已加载且符合条件的用户消息，也可从符合条件的用户消息操作直接发起。确认选择后，应用会请求服务端创建新的根会话，并把所选 prompt 恢复到新 Composer。
- Fork calls `POST /session/{sessionID}/fork` with the normalized project `directory`, optional `workspace`, and selected `messageID`. The server owns the forked history; Android transfers only the selected prompt through an application-scoped, one-time in-memory handoff and does not copy the old history into the Store. / Fork 使用规范化项目 `directory`、可选 `workspace` 和所选 `messageID` 调用 `POST /session/{sessionID}/fork`。fork 后的历史由服务端负责；Android 仅通过 application-scoped 一次性内存交接传递所选 prompt，不会把旧历史复制到 Store。
- Fork shares the fail-fast session-operation gate with send, abort, revert, and unrevert. The non-idempotent request is one-shot, with automatic retries and redirects disabled to prevent replay and duplicate forks. / Fork 与 send、abort、revert 和 unrevert 共用 fail-fast 会话操作门禁。非幂等请求按 one-shot 执行，并禁用自动重试与重定向，以避免重放和重复 fork。

## Upgrade and migration / 升级与迁移

- No manual data migration is required. A same-signer Android replacement install from public `0.3.0` is expected to preserve app-private DataStore data, Keystore-backed credential references, server profiles, and local preferences; the final release candidate must still pass the candidate-specific replacement-install device gate. / 无需手工数据迁移。使用相同签名从公开 `0.3.0` 执行 Android 覆盖安装预计会保留应用私有 DataStore 数据、Keystore 凭据引用、服务器 profile 和本地设置；最终发布候选仍须通过该候选专属的设备覆盖安装门禁。
- Session fork adds no persisted Android schema. Its selected-prompt handoff exists only in application memory and is consumed once when the new session opens. / Session fork 不新增 Android 持久化 schema；所选 prompt 的交接只存在于应用内存中，并在新会话打开时消费一次。
- Select the APK matching the device ABI. There is no universal APK or AAB, and OC Deck has no in-app updater. Compatible updates use Android replacement installation; uninstall-based rollback deletes app-private local data. / 必须选择与设备 ABI 匹配的 APK。当前不提供 universal APK 或 AAB，OC Deck 也没有应用内更新器。兼容更新使用 Android 覆盖安装；通过卸载回退会删除应用私有本地数据。
- Record necessary non-secret connection details outside the app and keep another way to access important servers. OC Deck still has no supported settings or credential export/restore workflow. / 请在应用外记录必要的非敏感连接信息，并保留访问重要服务器的其他方式。OC Deck 仍没有受支持的设置或凭据导出/恢复流程。

## Compatibility / 兼容性

- Minimum Android version: Android 8.0 / API 26. / 最低 Android 版本：Android 8.0 / API 26。
- Published APK ABIs: `arm64-v8a`, `armeabi-v7a`, and `x86_64`. / 发布 APK ABI：`arm64-v8a`、`armeabi-v7a` 和 `x86_64`。
- Formal `0.4.0` APKs use the bridge-free pure Kotlin STCP backend. The retained GoMobile implementation remains only in repository verification and maintainer-controlled manual emergency profiles through K10. / 正式 `0.4.0` APK 使用无 bridge 的纯 Kotlin STCP backend。保留的 GoMobile 实现到 K10 之前只存在于仓库验证与维护者控制的手动 emergency profile 中。
- Session fork requires a compatible OpenCode Server implementation of `POST /session/{sessionID}/fork`. OpenCode Server `1.17.7` remains `Observed only`, not a supported-version guarantee; other server versions remain `Unknown`. / Session fork 要求 OpenCode Server 兼容实现 `POST /session/{sessionID}/fork`。OpenCode Server `1.17.7` 仍仅标记为 `Observed only`，不构成受支持版本保证；其他服务端版本仍为 `Unknown`。
- The retained immutable GoMobile bridge coordinate is `io.github.ycfeng.ocdeck:frpc-stcp-visitor-gobridge:0.3.19-frp0.69.1-p6`, with Go module identity `v0.3.19`. The increment from `0.3.18` records the embedded `0.4.0` legal inventory; Go source, Go, x/mobile, upstream frp, Android API, NDK, and the p6 patch set are unchanged, but the artifact set is rebuilt and revalidated. / 保留的不可变 GoMobile bridge 坐标为 `io.github.ycfeng.ocdeck:frpc-stcp-visitor-gobridge:0.3.19-frp0.69.1-p6`，Go module identity 为 `v0.3.19`。从 `0.3.18` 提升是为了记录内嵌的 `0.4.0` 法律清单；Go 源码、Go、x/mobile、上游 frp、Android API、NDK 和 p6 patch set 保持不变，但制品集合会重新构建并校验。
- Automated checks do not replace candidate-specific target-ABI device, 16KB runtime, same-signer replacement-install, Direct/SSH/STCP, and real compatible-server Session fork gates. / 自动检查不能替代候选专属的目标 ABI 设备、16KB runtime、同签名覆盖安装、Direct/SSH/STCP 以及真实兼容服务端 Session fork 门禁。

See the versioned compatibility matrix linked from the release preamble. / 详见发布固定前言链接的版本化兼容性矩阵。

## Breaking changes / 破坏性变更

None at the persisted server-profile or OpenCode API contract level. Session fork is additive and does not change existing session operation behavior. / 持久化服务器 profile 与既有 OpenCode API contract 层面没有破坏性变更。Session fork 是新增能力，不改变现有会话操作行为。

## Deprecated and removed / 弃用与移除

- No user-facing connection mode, setting, or session operation is deprecated or removed. / 没有弃用或移除面向用户的连接方式、设置或会话操作。
- GoMobile verification, interoperability, symmetric, and manual emergency gates remain through K10; `0.4.0` does not remove them. / GoMobile 验证、互操作、对称与手动 emergency 门禁继续保留至 K10；`0.4.0` 不会移除这些门禁。

## Known issues / 已知问题

- Fork selection searches only eligible non-optimistic user messages already loaded on the active branch. / Fork 选择只搜索当前活动分支中已加载且符合条件的非 optimistic 用户消息。
- Session fork depends on compatible server endpoint behavior. A failed or uncertain network result is not automatically retried because replay could create a duplicate session. / Session fork 依赖兼容的服务端 endpoint 行为。失败或结果不确定的网络请求不会自动重试，因为重放可能创建重复会话。
- Provider management still requires broader real-server/provider and device validation. / Provider 管理仍需更广泛的真实 Server、Provider 与设备验证。
- The standalone Review route remains a placeholder; usable Git/session diff is in the session Changes tab. Model enabled/hidden settings remain local filters and do not modify OpenCode Server configuration. / 独立 Review route 仍为占位；可用 Git/session diff 位于会话 Changes tab。模型 enabled/hidden 设置仍只是本机过滤，不会修改 OpenCode Server 配置。
- Shell mode, session sharing, workspace/worktree flows, and PTY/terminal are not implemented. / Shell mode、session share、workspace/worktree 和 PTY/terminal 尚未实现。

## Security and privacy / 安全与隐私

- Fork requests carry the selected message identifier and normal project scope to the OpenCode Server that already owns the session. The selected prompt is retained only in application memory until the one-time handoff is consumed or cleared. / Fork 请求会把所选消息标识和正常项目范围发送给本就拥有该会话的 OpenCode Server。所选 prompt 只会保留在应用内存中，直到一次性交接被消费或清除。
- Non-idempotent fork requests disable automatic retries and redirects and share the session-operation gate to reduce replay and concurrent-operation risk. / 非幂等 fork 请求会禁用自动重试与重定向，并共用会话操作门禁，以降低重放和并发操作风险。
- Connect only to OpenCode Server, SSH, and frps endpoints you trust. Server operators, model providers, and network intermediaries may receive project content, prompts, attachments, and metadata. / 只连接可信的 OpenCode Server、SSH 和 frps endpoint。服务端运营者、模型 Provider 和网络中间方可能接收项目内容、prompt、附件和 metadata。
- Sensitive credentials and pins remain referenced through Android Keystore-backed storage and redacted from supported logs, diagnostics, and UI error paths. Public reports must replace sensitive values with `<redacted>`. / 敏感凭据与 pin 继续通过 Android Keystore 支持的存储引用，并在受支持日志、诊断和 UI 错误路径中脱敏。公开报告必须使用 `<redacted>` 替换敏感值。

## Downloads and verification / 下载与校验

The release workflow uploads exactly these assets: / Release workflow 精确上传以下 asset：

- `OCDeck_0.4.0_armeabi-v7a.apk`

GitHub may additionally show automatic source archives. They are not APKs and cannot be installed. Follow the versioned installation guide linked from the release preamble. / GitHub 还可能显示自动源码归档；它们不是 APK，无法安装。请遵循发布固定前言链接的版本化安装指南。

When only one ABI APK was downloaded, calculate its checksum and compare it with the same filename in `SHA256SUMS`: / 只下载一个 ABI APK 时，计算其 checksum，并与 `SHA256SUMS` 中同名文件比较：

```bash
sha256sum OCDeck_0.4.0_arm64-v8a.apk
grep 'OCDeck_0.4.0_arm64-v8a.apk' SHA256SUMS
```

On macOS: / macOS：

```bash
shasum -a 256 OCDeck_0.4.0_arm64-v8a.apk
grep 'OCDeck_0.4.0_arm64-v8a.apk' SHA256SUMS
```

On Windows PowerShell: / Windows PowerShell：

```powershell
Get-FileHash -Algorithm SHA256 .\OCDeck_0.4.0_arm64-v8a.apk
Select-String -LiteralPath .\SHA256SUMS -SimpleMatch "OCDeck_0.4.0_arm64-v8a.apk"
```

Use `sha256sum -c SHA256SUMS` only when all three listed APKs are present. `SHA256SUMS` verifies file consistency with the same Release but does not independently prove publisher identity. Download only from <https://github.com/ycfeng/ocdeck-android>.

只有三个列出的 APK 都存在时才使用 `sha256sum -c SHA256SUMS`。`SHA256SUMS` 可校验文件与同一 Release 中 checksum 文件的一致性，但不能独立证明发布者身份。只从 <https://github.com/ycfeng/ocdeck-android> 下载。
