## Release status / 发布状态

OC Deck `0.3.0` is the first public release with the pure Kotlin STCP backend as the formal default. It uses `VERSION_CODE=9` and requires no manual data migration from public `0.2.3`.

OC Deck `0.3.0` 是首个以纯 Kotlin STCP backend 作为正式默认实现的公开版本，使用 `VERSION_CODE=9`，从公开 `0.2.3` 升级无需手工数据迁移。

OC Deck is an independent, community-maintained Android client. It is not developed, endorsed, supported, or affiliated with the OpenCode project or Anomaly. Users must provide an OpenCode Server that they operate or trust. Original OC Deck code and documentation use the MIT License; bundled third-party components and assets retain their own licenses, notices, and trademark terms.

OC Deck 是独立社区维护的 Android 客户端，不是 OpenCode 项目或 Anomaly 官方开发、背书、支持或关联的产品。用户必须自行提供运行或信任的 OpenCode Server。OC Deck 原创代码和文档使用 MIT License；内含第三方组件和资产继续受各自许可证、通知和商标条款约束。

## Highlights / 亮点

- Formal Debug and Release assembly now use the bridge-free pure Kotlin STCP backend. Published APKs do not contain the GoMobile bridge or `libgojni.so`. There is no user-selectable backend or automatic runtime fallback. / 正式 Debug 与 Release 装配现使用无 bridge 的纯 Kotlin STCP backend；公开 APK 不包含 GoMobile bridge 或 `libgojni.so`。应用不提供用户可选 backend，也不会在运行时自动 fallback。
- The retained GoMobile path remains available for symmetric verification and a maintainer-controlled emergency build. `goMobileRelease` is a non-publishable comparison variant; the formal-identity, Release-signed `goMobileEmergencyRelease` profile is manual-only and cannot be published by a stable tag. / GoMobile 路径继续保留，用于对称验证及维护者控制的应急构建。`goMobileRelease` 是不可发布的对比 variant；使用正式 identity 与 Release 签名的 `goMobileEmergencyRelease` 仅允许手动运行，稳定 tag 不能发布该 profile。
- The Kotlin implementation covers frp wire v1/v2, default `tcpMux=true`, control/readiness lifecycle, Yamux flow control, listener ownership, bounded shutdown, control-epoch recovery, and Android default-network changes without clearing existing Store data. / Kotlin 实现覆盖 frp wire v1/v2、默认 `tcpMux=true`、control/readiness 生命周期、Yamux flow control、listener ownership、有界关闭、control epoch 恢复及 Android 默认网络变化，断线时不会清空已有 Store 数据。
- The Kotlin library implements all four public visitor payload combinations: encryption off/on and compression off/on, using frp-compatible AES-128-CFB and a bounded pure Kotlin Snappy framed codec. Current App-created STCP profiles still keep both options disabled and the UI does not expose them. / Kotlin library 已实现公共 visitor payload 的四种组合，即加密关闭/开启与压缩关闭/开启，使用兼容 frp 的 AES-128-CFB 和有界纯 Kotlin Snappy framed codec。当前 App 创建的 STCP profile 仍默认关闭两项能力，UI 也不暴露这些选项。
- Fixed, hash-pinned official frp `v0.69.1` interoperability covers wire v1/v2, all four payload modes, concurrent bidirectional traffic larger than the Yamux window, REST with live global/project SSE, typed negative cases, TLS, and frps restart/control-epoch recovery. Retained Android A/B gates compare GoMobile and Kotlin in separate processes. / 固定且经哈希校验的官方 frp `v0.69.1` 互操作覆盖 wire v1/v2、四种 payload 模式、大于 Yamux window 的并发双向流量、REST 与实时 global/project SSE、类型化负例、TLS，以及 frps 重启/control epoch 恢复。保留的 Android A/B 门禁会在独立进程中比较 GoMobile 与 Kotlin。
- The retained GoMobile bridge build is reproducible on the same platform across clean checkouts at different absolute paths with isolated Go caches. The gate compares the AAR, sources JAR, POM, checksum, API, provenance, and native metadata byte-for-byte. / 保留的 GoMobile bridge 可在同一平台、不同绝对路径的干净 checkout 和隔离 Go cache 下复现；门禁会逐字节比较 AAR、sources JAR、POM、checksum、API、provenance 与 native metadata。
- STCP settings support an optional exact TLS leaf-certificate SHA-256 pin stored through Android Keystore. Both retained backends enforce the pin before frp authentication data is sent and fail closed when the pin or its stored secret is unavailable. / STCP 设置支持可选的精确 TLS leaf 证书 SHA-256 pin，并通过 Android Keystore 存储。两个保留 backend 都会在发送 frp 认证数据前执行该 pin；pin 或其已保存 secret 不可用时会 fail closed。

## Upgrade and migration / 升级与迁移

- No manual data migration is required. A same-signer Android replacement install from public `0.2.3` is expected to preserve app-private DataStore data, Keystore-backed credential references, server profiles, and local preferences. / 无需手工数据迁移；使用相同签名从公开 `0.2.3` 执行 Android 覆盖安装预计会保留应用私有 DataStore 数据、Keystore 凭据引用、服务器 profile 和本地设置。
- The server-profile schema adds only an optional STCP TLS certificate-pin reference. Existing STCP profiles load without a configured pin. Adding a pin creates a purpose-specific Keystore reference; changing the frps address or port does not silently reuse the old endpoint's pin. / 服务器 profile schema 只新增一个可选 STCP TLS 证书 pin 引用。现有 STCP profile 会按未配置 pin 加载；新增 pin 时会创建专用 Keystore 引用，修改 frps 地址或端口时不会静默沿用旧 endpoint 的 pin。
- Existing STCP profiles automatically use the Kotlin backend after upgrade. There is no persisted backend selector and no automatic Kotlin-to-GoMobile fallback within an active generation. / 升级后，现有 STCP profile 会自动使用 Kotlin backend；不存在持久化 backend selector，也不会在活动 generation 内自动从 Kotlin fallback 到 GoMobile。
- If a severe Kotlin-specific regression requires the retained emergency path, maintainers must issue a same-signer GoMobile emergency build with a `VERSION_CODE` greater than `9`. Android downgrade installation is not a rollback mechanism. / 如果严重的 Kotlin 特有回归需要启用保留的 emergency 路径，维护者必须发布相同签名且 `VERSION_CODE` 大于 `9` 的 GoMobile emergency 构建；Android 降级安装不是回滚机制。
- Record necessary non-secret connection details outside the app and keep another way to access important servers. OC Deck still has no supported settings or credential export/restore workflow. / 请在应用外记录必要的非敏感连接信息，并保留访问重要服务器的其他方式。OC Deck 仍没有受支持的设置或凭据导出/恢复流程。
- Select the APK matching the device ABI. There is no universal APK or AAB, and OC Deck has no in-app updater. Compatible updates use Android replacement installation; uninstall-based rollback deletes app-private local data. / 必须选择与设备 ABI 匹配的 APK。当前不提供 universal APK 或 AAB，OC Deck 也没有应用内更新器。兼容更新使用 Android 覆盖安装；通过卸载回退会删除应用私有本地数据。

## Compatibility / 兼容性

- Minimum Android version: Android 8.0 / API 26. / 最低 Android 版本：Android 8.0 / API 26。
- Published APK ABIs: `arm64-v8a`, `armeabi-v7a`, and `x86_64`. / 发布 APK ABI：`arm64-v8a`、`armeabi-v7a` 和 `x86_64`。
- Formal `0.3.0` APKs use the pure Kotlin STCP backend and exclude the GoMobile bridge and `libgojni.so`. The GoMobile implementation remains in repository verification and manual emergency profiles only. / 正式 `0.3.0` APK 使用纯 Kotlin STCP backend，并排除 GoMobile bridge 与 `libgojni.so`；GoMobile 实现只保留在仓库验证与手动 emergency profile 中。
- The retained immutable GoMobile bridge coordinate is `io.github.ycfeng.ocdeck:frpc-stcp-visitor-gobridge:0.3.18-frp0.69.1-p6`. Compared with `0.2.3`'s `0.3.10-frp0.69.1-p1`, the p6 path includes native TLS-pin, shutdown, lifecycle, and diagnostics changes. The final `0.3.17` to `0.3.18` increment records the `0.3.0` legal inventory and changes the versioned Go module identity to `v0.3.18`; native BuildInfo, module-graph metadata, hashes, provenance, and the complete artifact set are therefore rebuilt. Go source, Go, x/mobile, upstream frp, Android API, NDK, and the p6 patch set are unchanged from `0.3.17`, but no byte-identity claim is made. / 保留的不可变 GoMobile bridge 坐标为 `io.github.ycfeng.ocdeck:frpc-stcp-visitor-gobridge:0.3.18-frp0.69.1-p6`。与 `0.2.3` 的 `0.3.10-frp0.69.1-p1` 相比，p6 路径包含 TLS pin、关闭、生命周期与诊断方面的 native 变化；最终从 `0.3.17` 到 `0.3.18` 的提升记录 `0.3.0` 法律清单，并把版本化 Go module identity 改为 `v0.3.18`，因此会重建 native BuildInfo、module graph metadata、hash、provenance 与完整制品集合。Go 源码、Go、x/mobile、上游 frp、Android API、NDK 与 p6 patch set 相对 `0.3.17` 保持不变，但不声明字节相同。
- Official frp `v0.69.1` is the pinned interoperability baseline, not a universal support guarantee for every frp version or deployment. The `p6` suffix identifies OC Deck's retained downstream GoMobile patch level, not a separately published official frp release. / 官方 frp `v0.69.1` 是固定互操作基线，不构成对所有 frp 版本或部署的普遍支持保证；`p6` 后缀表示 OC Deck 保留的 GoMobile 下游补丁级别，不是另一个官方 frp 发布版本。
- OpenCode Server `1.17.7` remains `Observed only`, not a supported-version guarantee. Other server versions remain `Unknown`. / OpenCode Server `1.17.7` 仍仅标记为 `Observed only`，不构成受支持版本保证；其他服务端版本仍为 `Unknown`。
- Automated checks cover bridge/API provenance, fixed-frp interoperability, Kotlin/GoMobile contract equivalence, bridge-free Kotlin packaging, signing, checksums, ABI isolation, and 16KB alignment. Every final release candidate must separately pass target-ABI device, 16KB runtime, replacement-install, and real STCP release gates. / 自动化检查覆盖 bridge/API provenance、固定 frp 互操作、Kotlin/GoMobile 契约等价、无 bridge Kotlin 打包、签名、checksum、ABI 隔离和 16KB 对齐。每个最终发布候选仍须独立通过目标 ABI 设备、16KB runtime、覆盖安装和真实 STCP 发布门禁。
- Target-ABI physical loading and 16KB runtime validation may use different devices. Physical ARM hardware combining the published ABI with a 16KB page size remains an unverified residual combination rather than an additional K7 gate. / 目标 ABI 物理加载和 16KB runtime 验证可使用不同设备；同时具备发布 ARM ABI 与 16KB page size 的物理硬件仍是未覆盖的残余组合风险，而不是额外的 K7 门禁。

See the versioned compatibility matrix linked from the release preamble. / 详见发布固定前言链接的版本化兼容性矩阵。

## Breaking changes / 破坏性变更

None at the persisted server-profile or OpenCode API level. The STCP runtime implementation changes from GoMobile to pure Kotlin, while the existing profile and manager contracts remain compatible. / 持久化服务器 profile 与 OpenCode API 层面没有破坏性变更。STCP runtime 实现从 GoMobile 切换为纯 Kotlin，但现有 profile 与 manager contract 保持兼容。

## Deprecated and removed / 弃用与移除

- No user-facing connection mode or setting is deprecated. / 没有弃用面向用户的连接方式或设置。
- The GoMobile bridge is removed from ordinary published APKs, but it is not removed from the repository. Verification, interoperability, and manual emergency paths remain through K10, which cannot begin until Kotlin-default completes one full stable public release cycle and the remaining release-device gates pass. / GoMobile bridge 已从普通公开 APK 中移除，但尚未从仓库删除。验证、互操作与手动 emergency 路径会保留至 K10；只有 Kotlin-default 完成一个完整稳定公开发布周期且剩余 Release 设备门禁通过后，才能开始 K10。

## Known issues / 已知问题

- Historical `0.1.0` and pre-K7 device evidence does not satisfy candidate-specific installation/loading, replacement-update, 16KB runtime, or real release-device STCP gates for `0.3.0`. / 历史 `0.1.0` 与 pre-K7 设备证据不能替代 `0.3.0` 候选特定的安装与加载、覆盖升级、16KB runtime 或真实 Release 设备 STCP 门禁。
- There is no user-visible backend selector or automatic runtime fallback. Recovery through GoMobile requires a separately built, higher-`VERSION_CODE`, same-signer emergency APK issued by maintainers. / 不提供用户可见 backend selector 或运行时自动 fallback；通过 GoMobile 恢复需要维护者另行构建并提供相同签名、具有更高 `VERSION_CODE` 的 emergency APK。
- Visitor payload encryption and compression are implemented and tested in the Kotlin library but are not exposed by the App UI or persisted App server-profile fields; App-created configurations continue to use `false`/`false`. / Visitor payload 加密与压缩已在 Kotlin library 中实现并测试，但 App UI 和 App 持久化服务器 profile 尚未暴露这些字段；App 创建的配置继续使用 `false`/`false`。
- Exact external Wi-Fi-to-cellular-to-Wi-Fi recovery evidence currently covers one reviewed physical ARM device. Expanding the same fail-closed contract to additional devices remains independent network hardening. / 精确的外部 Wi-Fi 到蜂窝再到 Wi-Fi 恢复证据目前覆盖一台已审查物理 ARM 设备；将相同 fail-closed 契约扩展到更多设备仍属于独立网络加固。
- STCP remains local-port mode only. The STCP secret authorizes the visitor and must not be described as end-to-end encryption for OpenCode traffic. / STCP 仍只支持本地端口模式。STCP secret 用于授权 visitor，不能描述为 OpenCode 流量的端到端加密。
- Provider management still requires broader real-server/provider and device validation. / Provider 管理仍需更广泛的真实 Server、Provider 与设备验证。
- The standalone Review route remains a placeholder; usable Git/session diff is in the session Changes tab. Model enabled/hidden settings remain local filters and do not modify OpenCode Server configuration. / 独立 Review route 仍为占位；可用 Git/session diff 位于会话 Changes tab。模型 enabled/hidden 设置仍只是本机过滤，不会修改 OpenCode Server 配置。
- Shell mode, session sharing, workspace/worktree flows, and PTY/terminal are not implemented. / Shell mode、session share、workspace/worktree 和 PTY/terminal 尚未实现。

## Security and privacy / 安全与隐私

- An optional STCP TLS pin must be exactly 64 lowercase hexadecimal characters representing the active non-CA leaf certificate's DER SHA-256. Both retained backends verify the exact pin, configured DNS name or IP address, certificate validity, and ServerAuth usage before sending frp authentication data. / 可选 STCP TLS pin 必须是 64 位小写十六进制，表示当前有效非 CA leaf 证书 DER 的 SHA-256。两个保留 backend 都会在发送 frp 认证数据前校验精确 pin、配置的 DNS 名称或 IP 地址、证书有效期与 ServerAuth usage。
- TLS pins are stored only through purpose-specific Android Keystore aliases. A configured alias whose secret is unavailable fails closed. Changing the frps address or port does not inherit the previous endpoint's pin. / TLS pin 只通过专用 Android Keystore alias 存储。已配置 alias 的 secret 不可用时会 fail closed；修改 frps 地址或端口不会继承旧 endpoint 的 pin。
- The Kotlin STCP implementation applies bounded frame, JSON, compression, Yamux queue, stream, and relay handling. Cancellation and JVM `Error` propagate, while user-visible failures remain typed, localized, and payload-free. / Kotlin STCP 实现对 frame、JSON、压缩、Yamux queue、stream 与 relay 执行有界处理；取消与 JVM `Error` 原样传播，面向用户的失败保持类型化、本地化且不含 payload。
- The library's visitor encryption flag is an frp-compatible payload option, not a general end-to-end security guarantee. Current App-created profiles leave it disabled. Protect frps and OpenCode traffic with an appropriate trusted TLS and deployment topology. / Library 的 visitor encryption flag 是兼容 frp 的 payload 选项，不是普遍的端到端安全保证；当前 App 创建的 profile 会保持关闭。应通过适当且可信的 TLS 与部署拓扑保护 frps 和 OpenCode 流量。
- Connect only to OpenCode Server, SSH, and frps endpoints you trust. Server operators, model providers, and network intermediaries may receive project content, prompts, attachments, and metadata. / 只连接可信的 OpenCode Server、SSH 和 frps endpoint。服务端运营者、模型 Provider 和网络中间方可能接收项目内容、prompt、附件和 metadata。
- Sensitive credentials and pins are referenced through Android Keystore-backed storage and redacted from supported logs, diagnostics, and UI error paths. / 敏感凭据与 pin 通过 Android Keystore 支持的存储引用，并在受支持日志、诊断和 UI 错误路径中脱敏。
- Do not include API keys, passwords, tokens, cookies, private keys, host fingerprints, certificate pins, provider headers, private server URLs, project content, prompts, or raw sensitive logs in public reports. Use `<redacted>`. / 公开报告不得包含 API key、密码、token、cookie、私钥、host fingerprint、证书 pin、provider header、私有服务器 URL、项目内容、prompt 或敏感原始日志，应使用 `<redacted>`。

## Downloads and verification / 下载与校验

The release workflow uploads exactly these assets: / Release workflow 精确上传以下 asset：

GitHub may additionally show automatic source archives. They are not APKs and cannot be installed. Follow the versioned installation guide linked from the release preamble. / GitHub 还可能显示自动源码归档；它们不是 APK，无法安装。请遵循发布固定前言链接的版本化安装指南。


On macOS: / macOS：

```bash
shasum -a 256 OCDeck_0.3.0_arm64-v8a.apk
```

On Windows PowerShell: / Windows PowerShell：

```powershell
Get-FileHash -Algorithm SHA256 .\OCDeck_0.3.0_arm64-v8a.apk
Select-String -LiteralPath .\SHA256SUMS -SimpleMatch "OCDeck_0.3.0_arm64-v8a.apk"
```

Use `sha256sum -c SHA256SUMS` only when all three listed APKs are present. `SHA256SUMS` verifies file consistency with the same Release but does not independently prove publisher identity. Download only from <https://github.com/ycfeng/ocdeck-android>.

只有三个列出的 APK 都存在时才使用 `sha256sum -c SHA256SUMS`。`SHA256SUMS` 可校验文件与同一 Release 中 checksum 文件的一致性，但不能独立证明发布者身份。只从 <https://github.com/ycfeng/ocdeck-android> 下载。
